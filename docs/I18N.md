# Langues extensibles de DIG! (#59)

Ce document décrit comment DIG! gère ses langues, comment en ajouter une sans tout traduire à la main, et ce qui reste en français tant qu'une langue n'est pas activée.

## 2. Registre central : `public/js/languages.js`

Le même fichier est chargé par le navigateur (`window.DigLanguages`) et par le serveur (`server/languages.js`). Plus aucun module ne recode « fr/en/nl/es ».

| Champ | Rôle |
|---|---|
| `code` | étiquette BCP 47 (`it`, `ru`, `pt-BR`…). `normalize('it-IT')` → `it` |
| `nativeName` | nom affiché au joueur dans sa langue (« Italiano », « Русский ») |
| `englishName` | nom donné aux modèles IA |
| `intl` | locale des dates, nombres et pluriels (`it-IT`) |
| `script` | écriture (Latn, Cyrl) : contrôle « mauvaise écriture » |
| `dir` | sens d'écriture (`<html dir>`) |
| `status` | `active` (proposée à tous, exigée dans les contenus), `preview` (masquée, testeurs seulement), `planned` (déclarée, inaccessible, aucune traduction lancée) |
| `builtin` | dictionnaire intégré à `i18n.js` (fr, en, nl, es) ou fichier généré |
| `flag` | drapeau **décoratif et facultatif**. Une langue n'est pas un pays : sans drapeau, une pastille neutre avec le code (« RU ») est affichée, toujours à côté du nom natif |

État actuel : fr, en, nl et es sont `active` ; it est `preview` (pilote) ; ru est `planned` (plus tard, pour tester le cyrillique).

Choix du joueur : mémorisé sur l'appareil (`localStorage dig_lang`), comme avant. Français = repli systématique de tout texte absent. La clé technique n'apparaît jamais si le texte existe en français.

### Accès testeur à une langue preview

- Ouvrir `https://dig.lodylands.com/?lang=it` : l'italien est choisi et mémorisé. « Italiano » apparaît ensuite dans ⚙ Paramètres → Langue sur cet appareil uniquement.
- Revenir en français : Paramètres → Langue → Français (ou `?lang=fr`).
- Un joueur qui n'a pas ouvert ce lien ne voit que les 4 langues actives, au premier lancement comme dans les paramètres.
- `?lang=ru` (planned) est ignoré.

### Pluriels

Une valeur peut être un objet `{ "$n": "count", "one": "…", "few": "…", "many": "…", "other": "…" }`. La forme est choisie par `Intl.PluralRules` dans la langue (le russe a `one/few/many`) ; `$n` nomme la variable du nombre (`n` par défaut). Les marques françaises `{s}` sont facultatives dans les autres langues. Le pilote italien utilise de vrais pluriels (« 1 danno per clic » / « 3 danni per clic »).

## 3. Traduction IA automatique : `tools/i18n`

```
node tools/i18n/cli.js status                 # couverture de chaque langue non intégrée
node tools/i18n/cli.js translate it           # simulation : taille de la file, lots, coût estimé (aucun appel)
node tools/i18n/cli.js translate it --apply [--batch 40] [--max-batches 3] [--max-usd 0.5]
node tools/i18n/cli.js check it               # contrôles qualité (code de sortie 1 si erreur)
node tools/i18n/cli.js build it               # régénère public/js/locales/it.js
node tools/i18n/cli.js export it relecture-it.csv
node tools/i18n/cli.js import it relecture-it.csv --by "Prénom"
node tools/i18n/cli.js correct it nav.shop "Negozio" --by "Prénom"
node tools/i18n/cli.js scan                   # textes oubliés dans le code
```

- **File idempotente et reprenable** : seulement les clés manquantes ou dont le français a changé (empreinte `src`). La mémoire est réécrite après chaque lot : une interruption ne perd que le lot en cours ; relancer reprend où l'on s'était arrêté. Une file vide ne fait aucun appel.
- **Budget** : nombre de lots par lancement, plafond de la commande (`--max-usd`, 0,50 USD par défaut) et plafond local partagé de `~/.config/dig/openai.env` (même journal que les icônes et les assistants IA de l'admin). La clé n'est jamais affichée ni journalisée. Coût estimé pour les 579 textes d'une langue : environ 0,03 USD.
- **Journal de coût** versionné, sans secret : `i18n/journal.jsonl` (date, langue, modèle, clés, acceptées, rejetées, coût).
- **Glossaire Dig** : `i18n/glossary.json` (pièces, gemmes, fragments, Auto-Dig, ligues, coffre, pioche… et consignes de ton, tutoiement, adaptation de l'humour). Ajouter une langue = ajouter sa colonne.
- **Aucun appel IA à la lecture** : le jeu ne lit que le fichier généré. Aucune image n'est nécessaire.
- **Corrections humaines protégées** : une entrée `origin: "human"` n'est jamais retraduite. Si le français change ensuite, elle est signalée « à revoir » (`check`), pas écrasée.

### Contrôles qualité (`check`)

| Erreur (texte non publié, repli FR) | Avertissement (relecture conseillée) |
|---|---|
| variable `{x}` perdue, renommée ou ajoutée | identique au français (oubli ?) |
| balise HTML différente | trop long pour mobile (libellés courts) |
| texte vide, pluriel sans forme `other` | emoji perdu ou changé |
| caractères cyrilliques dans une langue latine, ou latin dans une langue cyrillique | même traduction pour deux sources différentes |
| | langue improbable (mots outils d'une autre langue) |

Chaque réponse du modèle passe ces contrôles avant d'être enregistrée : une traduction qui casse une variable est rejetée et reste dans la file.

## 4. Ajouter une langue (exemple : russe)

1. `public/js/languages.js` : passer la ligne `ru` de `planned` à `preview`. Les autres langues se déclarent de la même façon, avec un `code` BCP 47.
2. `i18n/glossary.json` : vérifier la colonne de la langue.
3. `node tools/i18n/cli.js translate ru` (simulation), puis `--apply` (environ 15 lots de 40 textes).
4. `node tools/i18n/cli.js check ru` : 0 erreur ; lire les avertissements.
5. `npm test`, déploiement ordinaire. La langue reste masquée (accès `?lang=ru`).
6. Recette par un locuteur natif (voir `docs/I18N-PILOTE-IT.md`) ; corrections par `export` / `import`.
7. **Activation** (décision du propriétaire) : passer `status` à `active`. Le test « garde-fou d'activation » refuse une langue active non intégrée sous 98 % de couverture ou avec une erreur. À l'activation, la langue devient exigée pour publier les nouveaux contenus serveur (collections, badges, actualités, événements…) : les assistants IA de l'admin la proposent automatiquement, car leurs schémas lisent `CONTENT_LANGS`.

## 5. Ce qui reste en français pour une langue preview

- Contenus saisis en base : thème et nom de saison, collections saisonnières, badges, actualités, événements, articles de la boutique de cadeaux. Ils s'affichent en français tant que la langue n'est pas active, puis dans la langue pour les nouveaux contenus.
- Messages d'erreur détaillés du serveur et e-mails.

Rattrapage des contenus déjà publiés lors d'une activation : à faire avec une file de contenu serveur (table additive `content_translations`, même principe d'empreinte de source et de protection humaine). Non livré par #59 : voir la section « restant à faire » du rapport.
